## 시연 영상 계획

가이드라인 제약에 맞춰 실제 화면을 한 번에 녹화하고, 앞뒤 외에는 자르지 않음.

**제약이 만드는 문제와 대응**
- 문제 생성에 시간이 걸림(자료에 따라 분 단위). 중간을 자를 수 없으므로 기다리는 구간은 배속으로 재생하고 우측 상단에 배율을 표시함. 사전에 짧은 자료(1~2쪽)로 대기 시간을 줄여 둠
- 카드 등장 확률이 10~20%라 기다림이 길어질 수 있음. 마찬가지로 배속으로 처리하거나, 확률을 올린 빌드로 찍는다면 모킹 표시를 함. 정식 빌드로 찍는 쪽을 권함
- 자막을 쓸 수 없어 장면 설명은 발표자의 말로 함

**촬영 순서 (실제 동작만)**
1. 파일 앱에서 PDF를 공유로 보내기 → 올리기 시트에서 학습 주제 선택 → "올려 뒀어요"
2. 홈에서 "올린 자료 보기" → 문제를 만드는 중(진행 표시) → 준비됨 (대기는 배속)
3. 홈에서 학습 주제에 시험일 입력 → D-day 표시
4. YouTube 쇼츠에서 넘기기 → 문제 카드 등장 → OX 풀이 → 카드 안에서 결과 확인 → 영상으로 복귀
5. 단답 카드 → 입력 → 정답 확인
6. (가능하면) 스캔본 PDF를 올려 실패 이유 안내가 뜨는 장면

디버그 샘플 문제(`[샘플]`)는 릴리스 빌드에 없으므로, 영상은 릴리스 APK(배포 서버 연결)로 찍음. 서버에서 받은 문제가 없으면 카드가 뜨지 않음.

## 쓰면 안 되는 표현

- "중독", "숏폼이 주의력을 떨어뜨린다" 같은 인과 주장
- "숏폼 시간을 줄여 준다", "성적이 오른다" 같은 효과 주장. 검증한 적 없음
- "의지가 필요 없다". 대신 "한 번 켜 두면 매번 마음먹지 않아도 됨"
- 규칙이 하는 일을 AI가 판단하는 것처럼 말하기 (카드 등장 시점, 출제 주제, 채점, 재출제는 규칙)
- 정답이 맞다는 보증, 로컬 모델을 쓴다는 설명(지금은 OpenAI), 외부로 보내지 않는다는 설명
