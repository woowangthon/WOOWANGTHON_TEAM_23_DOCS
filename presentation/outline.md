# 발표 자료 구성 초안

2026-11-11 작성. 슬라이드를 만들기 전의 구성안임. 같은 날 서버(Fly.io)와 모델(OpenAI gpt-5.4-mini) 변경을 반영함.

## 먼저 정할 것

- 발표 시간, 슬라이드 형식(PDF, PPT), 제출 시점(11/15)에 발표 자료를 내야 하는지: 대회 안내에서 확인 필요
- 시연을 현장에서 실제 폰으로 할지, 시연 영상으로 할지
- 아래 구성은 발표 5~7분, 슬라이드 12장 안팎을 가정함. 시간이 다르면 줄이거나 늘림

## 심사 배점과 슬라이드 대응

| 항목 | 배점 | 답하는 슬라이드 |
|---|---|---|
| 문제 정의 | 20 | 2, 3 |
| 아이디어 차별성 | 15 | 4, 5 |
| 구현 완성도 | 25 | 6, 7, 8 |
| 기술 설계·이해도 | 10 | 9 |
| AI 활용도 | 10 | 10 |
| 현장 평가(전달력, 설득력, 질의응답) | 20 | 전체, 11, 12 |

구현 완성도 배점이 가장 커서 시연(슬라이드 6~8)에 시간을 가장 많이 씀.

|---|---|---|---|
| 1 | 스크롤 메이트 | 한 줄 소개: 배우고 싶은 자료를 올리면, 쇼츠를 넘기는 사이에 그 자료로 만든 문제가 찾아옴 | 앱 이름, 팀 23, 주제 "AI는 동료가 될 수 있을까 (청년의 삶)" |

| 5 | 기존 서비스와 차이 | 앱을 열 때만 개입하는 방식, 학습 피드를 따로 여는 방식과 달리 내 자료로 만든 문제가 숏폼 시청 중에 나옴 | 비교 표 (one sec, ScrollToll, ScrollEd, 우리) |
| 6 | 시연 1: 자료 올리기 | 공유하기로 PDF·PPTX를 보내면 학습 주제를 고르고 끝. 서버가 백그라운드에서 문제를 만듦 | 시연 영상 또는 화면 녹화 |
| 7 | 시연 2: 쇼츠 위 문제 카드 | 쇼츠를 넘기다 카드 등장, OX·단답 풀이, 정답 확인 뒤 바로 영상으로 복귀 | 시연 영상 |
| 8 | 시연 3: 내 일정에 맞춘 출제 | 시험일을 넣으면 가까운 주제가 더 자주 나오고, 틀린 문제는 간격을 두고 다시 나옴. 자료 목록에서 진행과 실패 이유 확인 | 홈(D-day), 자료 목록 화면 |
| 9 | 구조 | 앱 → 서버(Fly.io) → OpenAI API. 문제를 미리 만들어 기기에 저장하므로 카드는 오프라인에서도 뜸. 학습 주제와 시험일은 기기에만 저장 | `architecture.md`의 구성도 |
| 10 | AI가 하는 일, 규칙이 하는 일 | 문제 생성은 AI(OpenAI gpt-5.4-mini). 언제 띄울지, 어느 주제에서 낼지, 채점, 재출제는 규칙. 근거 문장이 없거나 원문에 없는 문제는 버림 | 역할 구분 표, 자동 검사 항목. 수치는 이전 모델 기준이라 넣을지 정해야 함 |
| 11 | 한계와 선을 지키는 방식 | 허용한 경우에만 등장하고 언제든 끌 수 있음. 쇼츠에 들어오고 넘기는 것만 감지하고 영상 내용·댓글·계정은 수집하지 않음. 올린 자료의 글자는 문제를 만들기 위해 OpenAI API로 전송됨. 새 모델의 문제 품질과 학습 효과는 검증하지 않았음 | 수집하는 것과 하지 않는 것, 외부로 전송되는 것 |
| 12 | 동료가 될 수 있는가 | 일을 나눠 맡고(출제), 먼저 찾아오고(쇼츠 사이), 기억하고(틀린 문제), 선을 지킴(허용 범위). 다음 단계 | 네 가지 요약 |

## 시연 순서 (시연 영상에 담을 장면)

실제 화면을 녹화하고 결과를 조작하지 않음. 디버그 샘플 문제(`[샘플]`)가 아니라 서버에서 받은 문제로 찍음.

1. 파일 앱에서 PDF를 공유로 보내기 → 올리기 시트에서 학습 주제 선택 → "올려 뒀어요"
2. 홈에서 "올린 자료 보기" → 문제를 만드는 중(진행 표시) → 준비됨
3. 홈에서 학습 주제에 시험일 입력 → D-day 표시
4. YouTube 쇼츠에서 넘기기 → 문제 카드 등장 → OX 풀이 → 영상으로 복귀
5. 단답 카드 → 입력 → 정답 확인
6. (가능하면) 스캔본 PDF를 올려 실패 이유 안내가 뜨는 장면. FE PR #38이 머지된 뒤에 가능함

카드 등장 확률은 10~20%라 녹화가 길어질 수 있음. 확률을 올린 빌드로 찍으면 영상에 그 사실을 표기해야 함.

## 쓸 수 있는 근거

| 내용 | 출처와 주의 |
|---|---|
| 숏폼 이용자 평일 시청 시간 Z세대 46.9분, 밀레니얼 75.8분 | 2022년 대학내일 20대연구소 조사. 연도 표시 필요 |
| 한 번 볼 때 연속 시청 10~20분 미만이 24%로 최다 | 2025년 상반기, 14세 이상 3,151명 대상. 청년 단독 수치 아님 |
| 주 이용 플랫폼 유튜브 쇼츠 89.6% | 2024년 10월, 20~60대 1,000명 대상. 청년 단독 수치 아님 |
| 시험 효과(인출 연습) | 교실 연구에서 효과 확인. 숏폼 사이 방식 자체의 효과는 검증하지 않음 |
| (이전 모델 선정 과정) 자동 검사 결함 없음 94%(qwen3.5:9b, 25조각), 새 프롬프트 83%(27조각) | `ai-scope.md`. 지금 쓰는 gpt-5.4-mini의 수치가 아님. 쓰려면 "모델 선정 과정에서 로컬 모델을 평가한 결과"라고 밝혀야 함. 결함 없음은 형식·근거 검사 통과이고 정답이 맞다는 뜻이 아님 |
| (이전 모델 선정 과정) 사람 채점 qwen3.5:9b 정답 6/6 | 지금 쓰는 모델의 수치가 아님. 모델당 6문항이라 표본도 작음. gpt-5.4-mini로 만든 문제는 평가하지 않아 지금 모델의 품질 수치는 말할 수 없음 |

출처 링크는 노션 아이디어 문서 "스크롤 메이트"에 있음. 슬라이드에 넣기 전에 원문을 다시 확인해야 함.

## 쓰면 안 되는 표현

- "중독", "숏폼이 주의력을 떨어뜨린다" 같은 인과 주장
- "숏폼 시간을 줄여 준다", "성적이 오른다" 같은 효과 주장. 검증한 적 없음
- "의지가 필요 없다". 대신 "한 번 켜 두면 매번 마음먹지 않아도 됨"
- 규칙이 하는 일을 AI가 판단하는 것처럼 말하기 (카드 등장 시점, 출제 주제, 채점, 재출제는 규칙)

## 발표에서 빼거나 "아직 없음"으로 말할 것

기획 문서에는 있지만 구현되지 않은 것. 구현된 것처럼 말하지 않음.

| 항목 | 상태 |
|---|---|
| 웹 체험판 | 만들지 않기로 함 |
| 오늘의 한마디, 시청 기록 | 앱에 자리만 있음. 서버 API 없음 |
| 오답노트 화면 | 앱에 없음 (서버 API만 있음) |
| 구글 로그인 | 이번 제출에 넣지 않음 |
| 인스타그램 릴스 | 감지 검증하지 않음. YouTube 쇼츠만 |
| 소규모 파일럿(지인 5~10명) | 하지 않음. 사용 수치를 말할 수 없음 |
| iOS | 범위 밖 |
| 틀린 문제 재출제, 자료 목록 | FE PR #38, #39 머지 전 |

## 질의응답 대비

| 질문 | 답 |
|---|---|
| 그냥 퀴즈 앱 아닌가 | 문제 생성은 입구임. 차별점은 내 자료로 만든 문제가 숏폼 시청 중에 먼저 찾아온다는 것 |
| 왜 도구가 아니라 동료인가 | 출제를 맡아 처리하고, 먼저 찾아오고, 틀린 것을 기억해 다시 물어봄. 허용한 범위 안에서만 움직임 |
| AI가 틀린 문제를 내면 | 근거 문장이 없거나 원문에 없는 문제는 버림. 근거 문장과 쪽수를 함께 저장함. 정답 채점은 표본이 작아 미검증이라고 밝힘 |
| 학습 효과가 있나 | 인출 연습의 효과는 연구 근거가 있음. 숏폼 사이 방식 자체는 검증하지 않았음 |
| 숏폼 시청을 정당화하는 것 아닌가 | 권장하지 않음. 시청 시간을 늘리는 장치가 없고 언제든 끌 수 있음 |
| AI가 감시하는 것 아닌가 | 쇼츠에 들어오고 넘기는 것만 감지함. 영상 내용·댓글·계정은 수집하지 않음 |
| 올린 자료는 어떻게 되나 | 글자만 뽑아 서버에 저장하고 원본 파일은 보관하지 않음. 글자는 문제를 만들기 위해 OpenAI API로 전송됨. 자료를 삭제하면 서버의 글자, 문제, 풀이 결과, 신고가 함께 지워짐 (README 자료 사용 안내) |
| 왜 로컬 모델이 아니라 OpenAI인가 | 처음에는 로컬 모델(qwen3.5:9b)을 평가해 골랐으나, 서버를 돌리던 Mac을 심사 종료까지 계속 켜 둘 수 없어 2026-11-11에 서버를 Fly.io로 옮기고 OpenAI API로 바꿈. 새 모델의 문제 품질은 아직 평가하지 않음 |
| 로그인이 없는데 | 이번 제출에서는 기기 ID와 기기별 한도로만 막음. 한계로 문서에 적음 |
| iOS는 | 시스템 제약으로 시청 중 개입 방법을 찾지 못함. 안드로이드만 지원 |

## 확인하지 못한 것

- 시연 순서의 장면들은 기기에서 아직 끝까지 확인하지 못함. 확인 결과에 따라 시연 순서를 바꿔야 할 수 있음
- 통계와 연구 출처는 노션 기획 문서의 내용을 옮긴 것이고 원문을 다시 확인하지 않음
- 발표 시간과 형식을 모름
